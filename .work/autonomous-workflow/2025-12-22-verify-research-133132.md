## Executive Summary

**Claude Code 2.0.42+ DOES include `agent_id` in SubagentStop hooks, making agent-task correlation possible.**

Key findings:
- **SubagentStop** (v2.0.42+): Includes `agent_id` and `agent_transcript_path`
- **SubagentStart** (v2.0.43+): Hook exists, minimal documentation on payload
- **PostToolUse**: Includes `tool_input` with Task tool's `description` field
- **No agent_id in PostToolUse**: Cannot identify agent at dispatch time

**Implication**: The autonomous workflow system should track task dispatch via PostToolUse (using tool_input.description) and correlate completion via SubagentStop (using agent_id).

## Research Question 1: Does PostToolUse hook include agent_id?

### Answer: NO

**Finding 1.1: PostToolUse Payload Schema**
- Source: https://code.claude.com/docs/en/hooks (Official Claude Code Hooks Reference)
- Confidence: HIGH
- Evidence:
```json
{
  "session_id": "abc123",
  "transcript_path": "/Users/.../.claude/projects/.../00893aaf-19fa-41d2-8238-13269b9b3ca0.jsonl",
  "cwd": "/Users/...",
  "permission_mode": "default",
  "hook_event_name": "PostToolUse",
  "tool_name": "Write",
  "tool_input": {
    "file_path": "/path/to/file.txt",
    "content": "file content"
  },
  "tool_response": {
    "filePath": "/path/to/file.txt",
    "success": true
  },
  "tool_use_id": "toolu_01ABC123..."
}
```

**Available fields in PostToolUse:**
- `session_id` (string): Session identifier (shared across all agents)
- `transcript_path` (string): Path to conversation JSON
- `cwd` (string): Current working directory
- `permission_mode` (string): Permission level
- `hook_event_name` (string): "PostToolUse"
- `tool_name` (string): Name of tool used (e.g., "Task", "Edit", "Write")
- `tool_input` (object): Tool-specific input parameters
- `tool_response` (object): Tool execution result
- `tool_use_id` (string): Unique identifier for this specific tool use (added in v2.0.43)

**Missing fields:**
- `agent_id` - NOT available in PostToolUse

- Source: Web search results - Claude Code PostToolUse Task tool examples

**Conclusion:** PostToolUse DOES include `tool_input.description` for Task tool, enabling task identification at dispatch time.

**Finding 3.2: SubagentStart Payload Information**
- Source: Multiple sources (blog posts, community documentation)
- Confidence: MEDIUM
- Evidence:

Mentioned fields in SubagentStart (not officially documented):
- `subagent_type` (string): Type of subagent being started
- Common base fields: `session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name`

**Note from search results:**

## Research Question 4: What other hooks help with agent dispatch/completion tracking?

### Answer: SubagentStop (v2.0.42+) includes agent_id

**Finding 4.1: SubagentStop Hook Enhancement**
- Source: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md (Official CHANGELOG)
- Confidence: HIGH
- Evidence:

From CHANGELOG v2.0.42:
```
Added `agent_id` and `agent_transcript_path` fields to `SubagentStop` hooks.
```

**This is the critical finding for the autonomous workflow system.**

**Finding 4.2: SubagentStop Payload (v2.0.42+)**
- Source: Combined from official CHANGELOG and https://blog.sd.idv.tw/en/posts/2025-11-20_claude-code-2.0.41-2.0.47-release-notes/
- Confidence: HIGH (confirmed by official CHANGELOG)
- Evidence:

SubagentStop payload structure (v2.0.42+):
```json
{
  "session_id": "abc123",
  "transcript_path": "~/.claude/projects/.../00893aaf-19fa-41d2-8238-13269b9b3ca0.jsonl",
  "permission_mode": "default",
  "hook_event_name": "SubagentStop",
  "stop_hook_active": true,
  "agent_id": "string",              // Added in v2.0.42
  "agent_transcript_path": "string"  // Added in v2.0.42
}
```

**New fields in v2.0.42:**
- `agent_id` (string): Unique identifier for the specific agent instance
- `agent_transcript_path` (string): Path to the agent's complete conversation transcript

**Finding 4.3: Version Timeline**
- Source: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
- Confidence: HIGH
- Evidence:

| Version | Addition |
|---------|----------|
| 2.0.42 | `agent_id` and `agent_transcript_path` to SubagentStop |
| 2.0.43 | `SubagentStart` hook event; `tool_use_id` to Pre/PostToolUseHookInput |

**Finding 4.4: Turboshovel's Current Implementation**
- Source: /Users/tobyhede/psrc/turboshovel/plugin/hooks/hooks-app/src/types.ts (lines 3-22)

### Gap 3: Relationship Between tool_use_id and agent_id
**Status:** Unknown
- PostToolUse includes `tool_use_id` (v2.0.43+)

**Why it matters:** If `tool_use_id` from PostToolUse (Task tool) correlates with `agent_id` from SubagentStop, the workflow system could definitively link task dispatch to completion.

**Recommendation:** Log both IDs during testing to verify correlation.

### Gap 4: SubagentStart Timing vs PostToolUse Timing
**Status:** Unknown

**Why it matters:** Affects which hook should be used for initial task tracking.

**Recommendation:** Test execution order empirically with detailed logging.

## Summary

### What We Know (HIGH Confidence)

1. **PostToolUse hook does NOT include agent_id**
   - Source: Official hooks reference
   - Includes: `tool_name`, `tool_input`, `tool_response`, `tool_use_id` (v2.0.43+)

2. **PostToolUse DOES include tool_input with Task tool's description**
   - Source: Official tool definitions, community examples
   - Task tool_input contains: `description` (3-5 words), `prompt` (full instructions)

3. **SubagentStop hook DOES include agent_id (v2.0.42+)**
   - Source: Official CHANGELOG
   - New fields: `agent_id`, `agent_transcript_path`
   - This enables reliable agent identification at completion time

4. **SubagentStart hook exists (v2.0.43+)**
   - Source: Official CHANGELOG
   - Payload poorly documented
   - Not listed in official hooks reference

5. **Turboshovel's types are outdated**
   - Source: Codebase analysis
   - Missing: `agent_id`, `agent_transcript_path`, `tool_input`, `tool_response`, `tool_use_id`
   - Comment about "no unique agent identifiers" is now incorrect (as of v2.0.42)

### Recommended Approach for Autonomous Workflow System

**Phase 1: Task Dispatch Tracking (PostToolUse)**
```typescript
// Hook: PostToolUse
// When: tool_name === "Task"
{
  "tool_name": "Task",
  "tool_input": {
    "description": "Fix login bug",  // Use this to identify task
    "prompt": "..."
  },
  "tool_use_id": "toolu_123..."  // May correlate with agent_id
}
```

**Phase 2: Agent Completion Tracking (SubagentStop)**
```typescript
// Hook: SubagentStop
{
  "agent_id": "unique-agent-id",
  "agent_transcript_path": "/path/to/agent/transcript.jsonl"
}
```

**Correlation Strategy:**
1. PostToolUse fires → store `tool_input.description` + `tool_use_id`
2. SubagentStop fires → receive `agent_id`
3. If `tool_use_id` correlates with `agent_id`, use direct mapping
4. Otherwise, use timing + description matching as fallback

### Version Requirements

**Minimum Claude Code version:** 2.0.42
- v2.0.42: `agent_id` in SubagentStop (REQUIRED)
- v2.0.43: `SubagentStart` hook + `tool_use_id` in PostToolUse (RECOMMENDED)
