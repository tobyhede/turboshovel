## Technical Correctness Assessment

### Type Guard Pattern Analysis

The plan correctly identifies that `unist-util-visit` types the callback parameter as `Node` (base type), not the specific AST node types. The type guard pattern:

```typescript
function isHeading(node: Node): node is Heading {
  return node.type === 'heading';
}
```

This is the idiomatic TypeScript solution. After calling `isHeading(node)`, TypeScript's control flow narrowing ensures:
1. `node.depth` is accessible (Heading has depth: 1-6)
2. `node` is assignable to `extractText`'s parameter type (Heading is in the union)

### Zod Transform Pattern Analysis

The plan correctly uses Zod's `.transform()` to convert the inferred type:

```typescript
.transform((n): TaskNumber => n as TaskNumber);
```

After parsing, `result.data.task` will be typed as `TaskNumber`, eliminating the need for the unsafe cast in `state.ts`.

**Key insight:** The `as TaskNumber` cast inside the transform is safe because:
1. Zod has already validated the number is positive and an integer
2. The transform runs after validation, so `n` is guaranteed valid
3. This is the standard pattern for branded types with Zod
