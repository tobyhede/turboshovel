**Dockerfile COPY will fail in npm mode:**
- Description: The Dockerfile always runs `COPY dist/*.tgz ./packages/` and `COPY plugin/ ./plugin/` regardless of build mode. In npm mode, the `dist/` directory is never created (no local build), so the Docker build will fail with "no source files were specified" or similar.
- Location: `/Users/tobyhede/psrc/turboshovel/scripts/Dockerfile.test:10-13`
- Action: Use multi-stage build or conditional COPY. Recommended approach: create separate Dockerfiles (Dockerfile.test.local and Dockerfile.test.npm) or use build stages. Alternatively, ensure dist/ always exists (even if empty) and use a `.dockerignore` strategy.

- Description: `verify-install.sh` passes `--build-arg SOURCE=npm` to Docker build, but `Dockerfile.test` never declares `ARG SOURCE`. This build argument is silently ignored, meaning the Dockerfile cannot conditionally change behavior based on mode.
- Location: `/Users/tobyhede/psrc/turboshovel/scripts/verify-install.sh:36` and `/Users/tobyhede/psrc/turboshovel/scripts/Dockerfile.test` (missing)
- Action: Add `ARG SOURCE=local` at top of Dockerfile and use conditional COPY or multi-stage build to handle both modes.

- Action: Verify the exact tarball name produced by `npm pack` for `@turboshovel/cli`. The glob pattern appears correct but should be tested. Consider using an explicit filename or listing the packages directory before install to debug.
