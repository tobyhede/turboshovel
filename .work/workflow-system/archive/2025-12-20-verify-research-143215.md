- **Location:** Web search, npm package micromark
- **Relevance:** micromark provides the same event/token-based approach as pulldown-cmark, making behavior preservation easier.
- **Confidence:** HIGH

- **Description:** TypeScript idiomatic error handling can use `neverthrow` for Result<T, E> types or Zod's `.safeParse()` pattern which returns a discriminated union of success/error. Both avoid try/catch for expected errors.

- **Confidence:** HIGH
- **Evidence:** neverthrow provides `ok()`, `err()`, and chainable methods like `andThen()`. Zod's safeParse returns `{ success: true, data } | { success: false, error }`.

## Recommended TypeScript Types

```typescript
// Branded type for step numbers (1-indexed, never zero)
type StepNumber = number & { readonly __brand: 'StepNumber' };

function createStepNumber(n: number): StepNumber | null {
  if (n < 1 || !Number.isInteger(n)) return null;
  return n as StepNumber;
}

// Discriminated union for actions
type Action =
  | { type: 'continue' }
  | { type: 'stop'; message?: string }
  | { type: 'goto'; target: StepNumber };

// Conditions - always both branches present
interface Conditions {
  pass: Action;
  fail: Action;
}

// Core step type
interface Step {
  readonly number: StepNumber;
  readonly description: string;
  readonly command?: Command;
  readonly prompts: readonly Prompt[];
  readonly conditions?: Conditions;
}

interface Command {
  readonly code: string;
}

interface Prompt {
  readonly text: string;
}

// Parse result using discriminated union
type ParseResult<T> =
  | { success: true; data: T }
  | { success: false; error: ParseError };

interface ParseError {
  message: string;
  location?: { line: number; column: number };
  suggestion?: string;
}
```

## Parsing Strategy Recommendation

### Option C (Recommended): Hybrid - micromark for tokenization, custom walker for semantics

**Rationale:**
1. **micromark tokenizes CommonMark identically to pulldown-cmark** - both follow the CommonMark spec
2. **Custom walker preserves Rust state machine logic** - can directly port the event handling
3. **Avoids reinventing markdown parsing** - no need to handle edge cases in markdown syntax itself
4. **Extensible** - micromark extensions available if needed for future syntax

**Implementation Sketch:**
```typescript
import { micromark } from 'micromark';
import { fromMarkdown } from 'mdast-util-from-markdown';

function parseWorkflow(markdown: string): ParseResult<Step[]> {
  // Phase 1: Parse to mdast AST
  const tree = fromMarkdown(markdown);

  // Phase 2: Walk AST with state machine (port of Rust logic)
  const state = new ParserState();

  for (const node of walkTree(tree)) {
    switch (node.type) {
      case 'heading':
        state.handleHeading(node);
        break;
      case 'code':
        state.handleCodeBlock(node);
        break;
      case 'paragraph':
        state.handleParagraph(node);
        break;
      // ... etc
    }
  }

  // Phase 3: Validate
  return state.finalize();
}
```

### Why Not Hand-Roll (Option B)?
- Would need to reimplement CommonMark parsing from scratch
- Error-prone and maintenance burden
- No benefit since we're extracting semantics, not changing markdown behavior

### Why Not Pure Library (Option A)?
- Need custom semantic extraction beyond standard AST walking
- State machine logic is domain-specific
- Library output may not match Rust event structure exactly

## Risk Assessment

### HIGH Risk: Implicit Prompt Detection
- **Issue:** Subtle state-dependent behavior - text becomes prompt only when no code block AND no explicit prompts
- **Mitigation:** Extensive test coverage, explicit state tracking

### MEDIUM Risk: Error Message Parity
- **Issue:** Rust error messages include line numbers from pulldown-cmark; JS equivalent may differ
- **Mitigation:** Accept slight differences in formatting, focus on semantic equivalence

### MEDIUM Risk: Unicode/Whitespace Edge Cases
- **Issue:** Different markdown parsers may handle edge cases differently
- **Mitigation:** Use micromark (CommonMark compliant), add specific tests for edge cases

### LOW Risk: Syntax Variation Coverage
- **Issue:** Many separator styles supported (`:`, `.`, `-`, etc.)
- **Mitigation:** Test matrix covering all combinations from Rust tests

### LOW Risk: Performance
- **Issue:** JavaScript may be slower than Rust
- **Mitigation:** Workflows are small documents; performance is not critical path

## Assessment

**Conclusion:**
The recommended approach is a hybrid strategy using **micromark/mdast-util-from-markdown** for markdown tokenization combined with a **custom state machine walker** that directly ports the Rust event-handling logic. This preserves behavioral fidelity while leveraging battle-tested markdown parsing.

2. `unist-util-visit` - Walk AST nodes
