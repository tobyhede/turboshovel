## BLOCKING (Must Fix Before Merge)

**Race Condition in Task Tracking:**
- Description: The task tracker uses `Date.now()` and `Math.random()` to generate task IDs, but concurrent Task tool dispatches could theoretically create duplicate IDs. The task state is updated via `manager.update()` which reads existing state, modifies it, and writes back - this is a classic read-modify-write race condition. If two Task tools are dispatched simultaneously, both could read the same state, append different tasks, and one write could clobber the other's task.
- Location: `/Users/tobyhede/psrc/turboshovel/plugin/hooks/hooks-app/src/workflow/hooks/task-tracker.ts:15-40`
- Action: While the collision probability is low, consider one of these approaches:
  1. Use atomic file operations with retry logic (append-based log instead of read-modify-write)
  2. Add a mutex/lock mechanism to serialize state updates
  3. Document the limitation explicitly if concurrent Task dispatches are not expected
  4. Use a more collision-resistant ID (e.g., include process ID or use crypto.randomUUID())

**Missing Error Handling in SubagentStop:**
- Description: The `handleSubagentStop` function calls `manager.update()` which can throw if the workflow state file becomes corrupted or deleted between `getActive()` and `update()`. This would cause the entire hook to fail without graceful degradation.
- Location: `/Users/tobyhede/psrc/turboshovel/plugin/hooks/hooks-app/src/workflow/hooks/subagent-stop.ts:60`
- Action: Wrap `manager.update()` in try-catch and return a warning message if the update fails, rather than allowing the exception to propagate and potentially break the hook pipeline.

**Type Safety Issue in CLI:**
- Description: The `next` command casts `state.step` to `number` without validation at line 91. If the state file is manually edited or corrupted, this could produce incorrect results or type confusion.
- Location: `/Users/tobyhede/psrc/turboshovel/plugin/hooks/hooks-app/src/cli/workflow-cli.ts:91`
- Action: Since `state.step` is already typed as `StepNumber` (branded number), remove the cast and trust the type system. If you need runtime validation, check that it's a valid StepNumber.
