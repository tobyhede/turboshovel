### S1: ARCHITECTURE.md references "commands" gate which does not exist

- **Description:** Architecture documentation references a "commands" gate in examples but this gate does not exist in the codebase
- **Location:** plugin/hooks/ARCHITECTURE.md, lines 191-193 and line 264
- **Benefit:** Prevents confusion about available TypeScript gates
- **Action:** The ARCHITECTURE.md shows:
  ```typescript
  // Gate name maps to module: "commands" -> gates/commands.ts
  const gates = await import('./gates');
  const result = await gates.commands.execute(input);
  ```

  Actual gates directory contains only:
  - `index.ts` - exports only pluginPath
  - `plugin-path.ts`

  The `commands` gate reference is demonstrative but misleading. Consider changing the example to use the actual `plugin-path` gate:
  ```typescript
  // Gate name maps to module: "plugin-path" -> gates/plugin-path.ts
  const gates = await import('./gates');
  const result = await gates.pluginPath.execute(input);
  ```

### S3: README.md workflow examples use --task flag where --step is correct

- **Description:** Several workflow examples incorrectly show `--task` for jumping to specific steps
- **Location:** plugin/hooks/README.md, lines 1087, 1149, 1206
- **Benefit:** Users can correctly use the CLI for step jumps
- **Action:** Examples like:
  ```markdown
  If more items -> `workflow next --task 1`
  ```

  Should use `--step` flag for jumping to steps:
  ```markdown
  If more items -> `workflow next --step 1`
  ```

  The CLI (workflow-cli.ts lines 127-131) shows:
  - `--step <n>` - Jump to specific step (for GOTO)
  - `--task <taskId>` - Specify which task (for parallel tasks)

  The documentation at lines 829-843 correctly documents `--step` but later examples inconsistently use `--task` for the same purpose.
