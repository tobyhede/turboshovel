## Issue 1: Circular Reference Handling Discrepancy

### Evidence Found

#### Test Expectation (plugin-gates.integration.test.ts)
- **File:Line**: `plugin/hooks/hooks-app/__tests__/plugin-gates.integration.test.ts:186`
- **Code**: `await expect(dispatch(input)).rejects.toThrow(/circular|depth|recursion/i);`
- **Comment (line 184-185)**: `// Should error or handle gracefully (not infinite loop) // Implementation decision: error on circular reference`

#### Implementation in gate-loader.ts
- **File:Lines**: `plugin/hooks/hooks-app/src/gate-loader.ts:100-104`
- **Code**:
```typescript
const gateRef = `${gateConfig.plugin}:${gateConfig.gate}`;
if (pluginStack.includes(gateRef)) {
  throw new Error(
    `Circular gate reference detected: ${pluginStack.join(' -> ')} -> ${gateRef}`
  );
}
```
- **Additional check (lines 108-112)**:
```typescript
if (pluginStack.length >= MAX_PLUGIN_DEPTH) {
  throw new Error(
    `Maximum plugin gate depth (${MAX_PLUGIN_DEPTH}) exceeded: ${pluginStack.join(' -> ')} -> ${gateRef}`
  );
}
```

#### Implementation in dispatcher.ts
- **File:Lines**: `plugin/hooks/hooks-app/src/dispatcher.ts:39-42`
- **Comment**: `ERROR HANDLING: Circular gate chain prevention (max 10 gates per dispatch). Prevents infinite loops from misconfigured gate chains.`
- **Code (lines 187-191)**:
```typescript
if (gatesExecuted >= MAX_GATES_PER_DISPATCH) {
  return {
    blockReason: `Exceeded max gate chain depth (${MAX_GATES_PER_DISPATCH}). Check for circular references.`
  };
}
```

#### CLI Error Handling
- **File:Lines**: `plugin/hooks/hooks-app/src/cli.ts:268-278`
- **Code**:
```typescript
} catch (error) {
  const errorMessage = error instanceof Error ? error.message : String(error);
  await logger.error('Hook dispatch failed', { error: errorMessage });
  console.error(
    JSON.stringify({
      continue: false,
      message: `Unexpected error: ${error}`
    })
  );
  process.exit(1);
}
```

### Analysis

There are **TWO DIFFERENT circular reference detection mechanisms** in play:

1. **Plugin Gate Chain Detection (gate-loader.ts)**:
   - Detects circular references in plugin-to-plugin gate references
   - **THROWS an exception** when circular reference is detected
   - Tracks call stack via `pluginStack` parameter
   - Maximum depth: 10 (MAX_PLUGIN_DEPTH)
   - This exception is caught in CLI and converted to `{"continue": false, "message": "..."}`

2. **Dispatcher Gate Chain Detection (dispatcher.ts)**:
   - Detects excessive gate chaining within a single dispatch
   - **RETURNS blockReason** when max depth is exceeded
   - Counts gates executed via `gatesExecuted` counter
   - Maximum depth: 10 (MAX_GATES_PER_DISPATCH)
   - This never reaches CLI exception handler

**The test is testing plugin-to-plugin circular references (mechanism #1), which DOES throw.**

**However, the documentation talks about gate chain depth limits (mechanism #2), which returns blockReason.**

### Conclusion
**NOT AN ISSUE** - Both behaviors are correct for their respective scenarios:

- **Plugin gate circular references** (gate-loader.ts): Throws exception → Test expects throw → CORRECT
- **Dispatcher gate chain depth** (dispatcher.ts): Returns blockReason → Different mechanism → ALSO CORRECT

The test and implementation are aligned. The confusion arises from conflating two separate circular reference protection mechanisms.

### Confidence Level
**HIGH** - Direct code evidence shows both mechanisms exist and work as designed.

### Recommended Action
**DOCUMENTATION CLARITY**: Update ARCHITECTURE.md to clarify the two distinct circular reference detection mechanisms:
1. Plugin-to-plugin gate references (throws exception)
2. Dispatcher gate chain depth (returns blockReason)

This is not a bug, but documentation could be clearer about these being separate safeguards.
