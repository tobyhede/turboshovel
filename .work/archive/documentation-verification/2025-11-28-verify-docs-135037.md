## BLOCKING (Must Address)

### 1. SessionStart Hook Not Fully Registered in hooks.json

**Description:** Documentation claims SessionStart is fully supported, but hooks.json only registers four hooks (PostToolUse, SubagentStop, UserPromptSubmit, SessionStart). However, the example context file itself admits SessionStart is not currently a supported hook in Claude Code.

**Current Documentation:**
- README.md (line 82-84): "SessionStart | session-start.md | Plugin injects agent selection guide"
- ARCHITECTURE.md (line 212): "SessionStart | session-start.md | Beginning of Claude session"
- CONVENTIONS.md (line 28): "SessionStart - At beginning of Claude Code session"

**Actual Implementation:**
- hooks.json registers SessionStart (line 13-19) with router command
- examples/context/session-start.md (line 24-26) states: "Note: SessionStart is not currently a supported hook in Claude Code. This file serves as a template..."

**Impact:** Users may attempt to use SessionStart context injection expecting it to work, but it won't actually trigger. Documentation misleads users about feature availability.

**Action:**
- Clarify in README.md and ARCHITECTURE.md that SessionStart registration exists but may not be functional in Claude Code
- Move session-start.md to disabled/template section or clearly mark as "Currently unavailable"
- Add note in CONVENTIONS.md that SessionStart should not be relied upon

### 2. Plugin Context Directory Does Not Exist

**Description:** Documentation claims plugin provides context files at `${CLAUDE_PLUGIN_ROOT}/context/` that auto-inject, but plugin/hooks/context/ directory does not exist. Only examples exist.

**Current Documentation:**
- README.md (line 66): "2. **Plugin context** (${CLAUDE_PLUGIN_ROOT}/context/) - fallback defaults"
- ARCHITECTURE.md (line 103-104): "├── context/ # Plugin-level context files (NEW) │ └── session-start.md"
- CONVENTIONS.md (line 41): "**All Claude Code hook types are supported.** Plugin provides default context for SessionStart"
- dispatcher.ts (line 200-209): Code searches for plugin-level context files

**Actual Implementation:**
- No plugin/hooks/context/ directory exists at all
- Only plugin/hooks/examples/context/ exists with template files (plan-start.md, session-start.md, etc.)
- context.ts buildContextPaths() and discoverContextFile() search for `${pluginRoot}/context/` but this directory never gets created
- Code will never find plugin context files because directory doesn't exist

**Impact:**
- CRITICAL: Context injection for plugin defaults silently fails without error. Users expect plugin to provide default context but it never materializes.
- Code path for "Plugin context (fallback)" in context.ts is dead code - will never return anything
- Documentation promises fallback defaults that don't exist

**Action:**
- Either create plugin/hooks/context/ directory with actual default context files, OR
- Remove all references to plugin context injection from documentation
- Update ARCHITECTURE.md to remove the context/ directory from structure
- Update context.ts discovery logic to not search for non-existent directory (performance improvement)
- Clarify in README.md that only project-level context injection is supported
