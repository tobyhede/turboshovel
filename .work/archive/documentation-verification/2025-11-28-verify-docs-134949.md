## BLOCKING (Must Address)

### Issue 1: Missing Plugin Context Directory

**Description:** Documentation claims plugin-level context files exist at `${CLAUDE_PLUGIN_ROOT}/context/` but this directory does not exist in the codebase.

**Current Documentation Claims:**
- README.md (lines 70-76): "Context Injection (AUTOMATIC): Always runs first... plugin/context/"
- ARCHITECTURE.md (lines 103-104): "context/ # Plugin-level context files (NEW)"
- CONVENTIONS.md (lines 41-42): "Plugin context (fallback): `${CLAUDE_PLUGIN_ROOT}/context/{name}-{stage}.md`"
- context.ts code (lines 69-80) attempts to discover plugin context but directory doesn't exist

**Actual Implementation:**
- Only project-level `.claude/context/` directory exists and is used
- Plugin provides default context files in `plugin/hooks/examples/context/` directory instead
- Examples contain: code-review-start.md, plan-start.md, session-start.md, test-driven-development-start.md

**Impact:** Users following documentation will expect plugin fallback context injection to work, but the plugin/context directory does not exist. The code handles missing directories gracefully (returns null), but documentation sets false expectations about available default context files.

**Location:**
- Documentation: README.md (lines 70-76), ARCHITECTURE.md (lines 103-104, 160), CONVENTIONS.md (lines 41-42, 96-99)
- Code: plugin/hooks/hooks-app/src/context.ts (lines 69-80)
- Missing Directory: plugin/hooks/context/ (does not exist)
- Actual Examples: plugin/hooks/examples/context/ (exists)

**Action:**
1. Clarify that plugin does NOT currently provide default context files via plugin/hooks/context/
2. Update documentation to reference example context files in plugin/hooks/examples/context/
3. Either create plugin/hooks/context/ directory with default files OR update all documentation references to remove claims about plugin-level context fallback

- ARCHITECTURE.md (lines 207-223): Table lists all 12 hook events with descriptions

**Actual Implementation (hooks.json):**
Only 4 hook events are registered:

- SubagentStop
- UserPromptSubmit
- SessionStart

Missing registrations (8 events):
- SessionEnd
- SlashCommandStart
- SlashCommandEnd
- SkillStart
- SkillEnd
- PreToolUse
- Stop
- Notification

**Code Evidence:**

**Location:**

**Action:**
1. Either register all 12 hook events in hooks.json OR

1. **Plugin context directory doesn't exist** - causes incorrect expectations about default context file fallback
