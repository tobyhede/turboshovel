## BLOCKING (Must Address)

**Missing error handling for invalid glob patterns:**
- Description: Plan does not specify how to handle invalid glob patterns or minimatch failures. If a user provides malformed patterns (e.g., unmatched brackets `[abc`, invalid regex in pattern), the gate system could throw unhandled exceptions during pattern matching.
- Location: Task 3 (gateMatchesFilePattern implementation), Task 4 (dispatcher integration)
- Impact: Runtime crashes when gates.json contains invalid patterns. Users would see cryptic errors instead of actionable validation messages. Critical because gates run automatically on file operations.
- Action: Add error handling in Task 3:
  1. Wrap `minimatch` call in try-catch
  2. Log warning with invalid pattern details
  3. Return `false` (skip gate) for invalid patterns
  4. Add test case for invalid pattern handling

  Example addition to Task 3:
  ```typescript
  try {
    const matches = minimatch(relativePath, pattern, {
      matchBase: false,
      dot: true,
    });
    // ... rest of logic
  } catch (error) {
    logger.warn('Invalid file pattern', { pattern, error: error.message });
    return false; // Skip gate on invalid pattern
  }
  ```

**Missing error messages for pattern validation failures:**
- Description: When a pattern fails to match or is invalid, users have no feedback about WHY the gate was skipped. Debug logging exists but requires TURBOSHOVEL_LOG_LEVEL=debug, which users won't have enabled by default.
- Location: Task 5 (debug logging)
- Impact: Poor user experience - gates silently skip without explanation. Users cannot debug their gates.json configuration. Violates "error messages with sufficient context" principle from code-review.md.
- Action: Add user-facing warning logs (info level, not debug) in Task 5:
  1. Log when ALL patterns fail to match (gate skipped)
  2. Include file path and patterns that were tried
  3. Add test verifying warning message appears

  Example addition:
  ```typescript
  // After pattern loop returns false
  logger.info('Gate skipped - file does not match any pattern', {
    relativePath,
    patterns: gateConfig.file_patterns,
    gate: gateName // Pass from dispatcher
  });
  ```

**No pattern validation at configuration load time:**
- Description: Invalid patterns are only detected at runtime (when files are edited). Configuration should be validated when gates.json is loaded to fail fast with clear errors.
- Location: Missing task - should be added before Task 3
- Impact: Users edit gates.json with typos/invalid patterns, but don't discover errors until they edit a file. Wastes time in debugging cycle. Violates "error handling approach specified" criterion.
- Action: Add new task (Task 2.5) to validate patterns on config load:
  1. Create `validateFilePatterns(config)` function
  2. Call during config loading in dispatcher initialization
  3. Test each pattern with minimatch against empty string to detect syntax errors
  4. Throw descriptive error if any pattern is invalid
  5. Add test cases for invalid pattern detection
