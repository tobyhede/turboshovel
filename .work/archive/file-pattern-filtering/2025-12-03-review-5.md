## NON-BLOCKING (May Be Deferred)

**README.md monorepo example missing `on_pass` field:**
- Description: The monorepo example in README.md shows gates with only `on_fail: "BLOCK"`, omitting the `on_pass` field. While this works (the system has defaults), it's inconsistent with the comprehensive examples in SETUP.md and CLAUDE.md which show both fields.
- Location: plugin/hooks/README.md:184-191
- Action: Add `"on_pass": "CONTINUE"` to both `backend:check` and `frontend:check` gates for consistency with other examples and to teach the complete configuration pattern.

**SETUP.md pattern table example could clarify recursive matching:**
- Description: The pattern examples table shows `src/**/*.ts` matching both `src/index.ts` and `src/lib/utils.ts`. While technically correct (because `**` matches zero or more directories), it might confuse users who expect `**` to require at least one directory. The implementation is correct, but the example could be clearer.
- Location: plugin/hooks/SETUP.md:170-176
- Action: Consider adding a note explaining that `**` matches zero or more directories, or use separate patterns `src/*.ts` and `src/**/*.ts` to show both cases explicitly.

**Performance section could mention caching opportunities:**
- Description: The performance considerations section mentions O(n*m) complexity and suggests consolidating gates for >100 patterns. It doesn't mention that pattern matching happens once per PostToolUse event, which is already quite efficient. Users might over-optimize prematurely.
- Location: plugin/hooks/SETUP.md:234-239
- Action: Add context that pattern matching happens once per file edit, and that performance concerns only matter for projects with hundreds of patterns evaluated on every edit.
