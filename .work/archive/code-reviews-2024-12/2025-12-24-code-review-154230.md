## NON-BLOCKING (May Be Deferred)

**Session file type definition duplication:**
- Description: The session file structure `{ active_workflow: string | null; stashedWorkflowId?: string }` is defined inline in both `loadSession()` and `saveSession()` methods. This creates a maintenance burden if the structure evolves (e.g., adding additional session properties in future).
- Location: plugin/hooks/hooks-app/src/workflow/state.ts:296-298, 305-308
- Action: Consider extracting to a named type `SessionData` at the top of the file alongside other types, or define it in types.ts if it needs to be shared. This makes the structure explicit and ensures consistency.

**Inconsistent error handling pattern:**
- Description: `getAgentBinding` returns `null` for non-existent workflow (line 247), but `updateAgentBinding` throws an error for the same condition (line 261). This inconsistency makes the API less predictable - callers must handle different error patterns for related operations.
- Location: plugin/hooks/hooks-app/src/workflow/state.ts:247, 261
- Action: Consider making both methods consistent. Either both return null for missing workflows (caller checks return value), or both throw (caller uses try-catch). Throwing is generally preferred for state mutations like `updateAgentBinding`, so consider having `getAgentBinding` also throw for consistency, or document the rationale for the difference.

**Missing JSDoc for private helper methods:**
- Description: The new private methods `loadSession()` and `saveSession()` lack JSDoc comments explaining their purpose, especially important given they handle the session file format and error handling (e.g., swallowing read errors in loadSession).
- Location: plugin/hooks/hooks-app/src/workflow/state.ts:296, 305
- Action: Add JSDoc comments explaining that `loadSession()` returns default session state if file doesn't exist (not an error condition), and `saveSession()` creates parent directories if needed.

**Pop cleanup logic not tested for workflow deletion edge case:**
- Description: The `pop()` method includes logic to clean up if the stashed workflow was deleted (lines 332-336), returning null and clearing stashedWorkflowId. While there's a test "returns null if stashed workflow was deleted", the test doesn't verify that the stashedWorkflowId is actually cleared from the session file.
- Location: plugin/hooks/hooks-app/__tests__/workflow/state.test.ts:362-371
- Action: Add an assertion in the "returns null if stashed workflow was deleted" test to verify `await manager.getStashedWorkflowId()` returns null after the failed pop, confirming the cleanup actually happened.
