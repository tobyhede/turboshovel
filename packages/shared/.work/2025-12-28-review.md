## BLOCKING (Must Fix Before Merge)

**TaskIdSchema incorrectly transforms string to TaskId object:**
- Description: The `TaskIdSchema` at line 115-117 of `schemas.ts` uses `z.string().transform((s): TaskId => s as unknown as TaskId)`, which expects a string input. However, `TaskId` is an interface `{ readonly task: TaskNumber; readonly subtask?: string }` that persists to JSON as an object, not a string. When WorkflowStateManager loads persisted state containing TaskId objects in `pendingTasks`, `agentBindings.taskId`, or `parentTaskId`, the schema will fail validation with "Expected string, received object" errors. This was verified by testing with actual TaskId objects - the schema rejects valid persisted data.
- Location: packages/shared/src/schemas.ts:115-117, 140, 142, 149
- Action: Replace `TaskIdSchema` with an object schema that matches the TaskId interface structure. The schema should be:
```typescript
const TaskIdSchema = z.object({
  task: TaskNumberSchema,
  subtask: z.string().optional()
});
```
This will correctly validate and transform the persisted JSON object structure `{ task: number, subtask?: string }` to the branded TaskId type.

```typescript
export interface TaskId {
  readonly task: TaskNumber;
  readonly subtask?: string;
}
```
